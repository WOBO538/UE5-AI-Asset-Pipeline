## 2. 测什么 / 不测什么

**测了**：解压 → 递归找 `Content` → 复制到 `Imported` → 生成 `import_manifest.json` → 写 `trigger.txt` → 归档 zip。

**没测**：

**测试数据**：造 N 个 `.uasset`（每个约 320 B），放在 `Pack/Content/Stylized/Props/Group{n}/` 三层嵌套结构里。
**不含图片**，因此不会触发 ComfyUI 分支。

## 3. 外部流转层：实测结果

| 包内资产 | manifest 条数 | 实际复制文件数 | **纯处理**（中位数） | **含防半写等待**（中位数） |
|---:|---:|---:|---:|---:|
| 50 | 50 | 50 | **0.047 s** | 2.055 s |
| 150 | 150 | 150 | **0.107 s** | 2.120 s |
| 310 | 310 | 310 | **0.212 s** | 2.220 s |

原始数据：

```json
[
  {"assets_in_zip": 50,  "real_median_s": 2.055, "real_all_s": [2.070, 2.051, 2.055], "pure_median_s": 0.047, "pure_all_s": [0.048, 0.045, 0.047]},
  {"assets_in_zip": 150, "real_median_s": 2.120, "real_all_s": [2.120, 2.115, 2.189], "pure_median_s": 0.107, "pure_all_s": [0.107, 0.107, 0.104]},
  {"assets_in_zip": 310, "real_median_s": 2.220, "real_all_s": [2.223, 2.210, 2.220], "pure_median_s": 0.212, "pure_all_s": [0.212, 0.206, 0.217]}
]
```

### 怎么读这两列

- **纯处理**：真正的 I/O 成本，随资产数**近似线性**，约 **0.7 ms / 资产**。
- **含等待**：多出来的 ~2 秒几乎恒定，来自 `is_file_complete()`——它按 1 秒间隔采样 zip 大小，连续两次一致才认为写入完成（防止读到正在拷贝的半截包）。**这是固定开销，与资产数无关。**

所以"310 个资产的包，外部流转 2.2 秒"是真实可复现的；其中 2.0 秒是故意等的。

## 5. AI 语义层：按代码参数推算

代码里 `BATCH_SIZE` 默认 **20**（`analyze.py`），模型 `deepseek-chat`，`temperature=0.1`。

| 资产数 | 批次数 | 单批耗时（历史区间 10–30 s） | 推算总耗时 | 推算成本（¥0.02/批） |
|---:|---:|---|---:|---:|
| 20 | 1 | 10–30 s | 10–30 s | ¥0.02 |
| 300 | 15 | 10–30 s | **2.5–7.5 min** | ≈ ¥0.3 |

> **重要更正**：`< ¥0.02 / 批` 指的是**一批 20 个资产**，不是 300 个。300 个资产要跑 15 批，成本约 ¥0.3、耗时数分钟。
> 之前 README 和作品集卡片上把"20 资产/批"的参数写成"300+ 资产"的口径，是不准确的，已在本文与 README 中更正。

缓存命中时可以完全跳过 API：内容寻址 key = `SHA256(asset_path + mtime毫秒 + file_size)`，TTL 30 天，重复资产重跑近乎零成本。

## 6. 正确的口径

| 说法 | 成立吗 | 应该说成 |
|---|---|---|
| 单批 300+ 资产 < 5 秒 | ❌ 只在**不含 AI** 时成立 | 300+ 资产的流转与校验在 5 秒内完成（外部层 2.2 s + 校验数秒） |
| 端到端 300+ 资产 < 5 秒 | ❌ | 不含 AI 5 秒内；含 AI 为分钟级（约 15 批 × 10–30 s） |
| AI 成本 < ¥0.02/批 | ⚠️ 需限定批大小 | 20 个资产/批约 ¥0.02；300 个资产约 ¥0.3 |
| 310 个资产、修复 15 处命名 | ✅ | 原样保留 |
| 轮询 9.9 ms 非阻塞 | ✅ | 原样保留 |

**对外统一口径（推荐）**：

> 单批 300+ 资产：外部流转层 0.2 秒出清单，规则校验秒级完成；AI 语义层按 20 个资产一批调用，300 个资产约需数分钟、成本约 0.3 元。缓存命中时零 API 调用。

## 7. 复现方法

```powershell
# 1. 造测试包（50 / 150 / 310 个 .uasset，三层嵌套）
# 2. 直接调用 process_zip，跳过轮询主循环
python D:\dsh_ta\bench_pipeline.py
# 结果写到 D:\dsh_ta\bench\result.json
```

脚本要点：
- 每种规模跑 3 次取中位数
- 分别测「含 `is_file_complete` 等待」与「绕过等待（monkeypatch 成立即 True）」两种口径
- 每次跑之前清空 `Processing` / `Imported` / `Saved`，避免缓存与残留污染
